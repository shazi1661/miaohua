安卓引擎与电脑版引擎的一致性 —— 结论
================================================
记录时间：2026-10-03（第三次修订，结案）
结论：**两边一致** —— 32 条可比用例，核心 0 条不同。

★★★ 前两次结论都作废 ★★★
------------------------------------------------
第一次：「发现 5 条真实差异」—— 作废，是坏工具的假象。
第二次：「差异未知」—— 作废，那时候工具还没修好。

现在这一版工具是可信的，方法见下。

为什么直接比输出没有意义
------------------------------------------------
语气风格每次会【随机挑】一个前缀、一个颜文字、一个后缀。
同一个引擎连跑两次，57 个用例里就有 27 个不一样。
→ 比最终输出看到的全是随机性。

正确的做法（现在的 check-engines.ps1）
------------------------------------------------
1. 用【电脑版规则 pc\rules.txt】跑安卓引擎（RulesCheck），
   拿到每条用例的 IN / OUT。
2. 电脑版这边【不能用 --selftest】—— 自检输出里有很多章节，每个章节
   的规则和目的都不同（幂等性章节会把结果再跑一遍），按 IN 取第一次
   出现的 OUT 会拿到别的章节的结果。第一次那 5 条假差异就是这么来的。
   改用 `Miaohua.exe --trace <用例…>`：它用真实的 rules.txt、真实的
   代码路径，而且带固定随机种子（new Random(7)），每次跑都一样。
3. 把两边输出里【所有样式池短语（726 条）】删掉，只留确定性核心，
   再逐条比。
4. 结果：32 条一致，0 条不同。

逐步 trace（更细的对比手段，推荐以后先用它）
------------------------------------------------
· 电脑版：Miaohua.exe --trace "文本1" "文本2" …
· 安卓  ：java RulesCheck <规则> <输出> <用例文件> trace
            （第 4 个参数写 trace，会额外写出 <输出>.trace）

两边都打了同样名字、同样顺序的 9 个点：
    000 input / 001 stripClosers / 002 stripDecorations#1 / 003 peelPrefix
    004 peelSuffix / 005 afterTruncateCloser / 006 stripDecorations#2
    007 applyRules / 008 decorateAll

用法：逐步对比两份 trace，【第一个出现分歧的那一步】就是答案。
注意：从 008 起两个引擎的步骤编号不再对应（安卓把装饰放在 applyRules
之后另一段里），所以 008 这一格不能直接比；000-007 是可以逐步逐字比的。

这次就是靠它找到唯一的结构差异的。

这次顺带修掉的一处真实差异
------------------------------------------------
电脑版在【剥完包装之后】还会再调一次 StripStaleDecorations，安卓没有。
逐步 trace 显示 000-005 六步两边逐字一致，唯独 006 这一步安卓缺失。

含义：用户转化过一次、又接着打字之后，引擎自己留下的旧装饰会被顶到
文字中间，"是否已经装饰过"那类只看结尾的判断全都看不见它，于是下一轮
把自己的产物当成用户的话又追加一段 —— 和当初在手机上发现的重复写入
是同一类问题，只是这一支当初没搬过去。

已经补到安卓（Rules.java 的 transform 里，applyRules 之前），补完再跑
逐条对比：32 条 0 差异。

（第一次也补过这一处，当时工具是坏的，显示"5 条变 6 条更差"，
 那个判断作废。补这一处本身是对的。）

网址非幂等问题 —— 已修（2026-10-03）
------------------------------------------------
自检里那条 NOT IDEMPOTENT 的【真正原因】不是"网址"本身：

  输入  https://example.com/a?b=1&c=2
  一遍  别、别自作多情了！https://example.com/a?b=1&c=2，……其实我，也不是不想听啦
         ↑ 只加了语气包装，【没有加颜文字】
  两遍  别、别自作多情了！https://example.com/a?b=1&c=2喵！(｀・ω・´)，……其实我，也不是不想听啦
         ↑ 第二遍文本"已经不只是网址了"，于是装饰也加上了 → 两次结果不同

根因：整段都是受保护内容（纯网址）时，【装饰】那一步会跳过
      （DecorateAll 里的 HasContentOutsideProtected 检查），
      但【语气包装】那一步没做同样的检查，照样往前缀后缀加东西。
      第一遍包装了没装饰，第二遍因为多了包装就不再是"纯网址"，装饰也来了。

修法（两边一起改）：
  电脑版 Miaohua.cs：包装之前加 bool wrappable = HasContentOutsideProtected(plain);
                      opener / closer 都加上 !wrappable 就不生成。
  安卓   Rules.java：同样加 boolean wrappable = hasContentOutsideProtected(plain);

验证：
  · 纯网址输入现在【完全不改动】—— 一遍 = 两遍 = 原文，幂等 ✓
    （附带好处：拿"别、别自作多情了！"去包一个裸链接本来就没道理）
  · 电脑版自检：不幂等条数 1 → 【0】✓
  · 两引擎逐条对比：32 一致 / 0 不同 ✓

仍然开着的一件事
------------------------------------------------
没有。引擎这一块目前是干净的（32/32 一致、自检 0 条不幂等）。
以后改引擎，先跑 check-engines.ps1 和 --selftest。

硬规则
------------------------------------------------
改引擎必须两个引擎一起改。今天的重复写入 bug 就是只改了一边造成的。
