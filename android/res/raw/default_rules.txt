# ---------------- 小模型语气（安卓专用 ✗ 默认关）----------------
#
# 打开以后 ✗ 关键词判不出语气时 ✗ 会问一下内置的小分类器 ✓
#
#     小模型语气 = true
#
# ★ 它是什么：
#     一个 7MB 的【字符 n-gram + softmax】分类器 ✗ 不是会说话的大模型 ✓
#     纯 Java 计算 ✗ 微秒级 ✗ 不发热 ✗ 不耗电 ✗ 不联网 ✓
#
# ★ 实测数据（10 个难例 ✗ 对象是"短回复要看上文才判得对"的那种）：
#     3B 大模型（2GB）    6 / 10
#     7B 大模型（4.4GB）  8 / 10
#     这个小分类器（7MB） 8 / 10    ← ★ 体积 1/630 ✗ 准确率持平 ✓
#
# ★ 为什么它能行：
#     "好""嗯""没事的"这种短回复本身没情绪词 ✗ 
#     只有看【对方刚说了什么】才判得对 ✓
#     分类器就是专门学这个映射的 ✗ 不需要"理解"✗ 只要模式匹配 ✓
#
# ★ 实测：上下文有多重要 ★
#     没有上文    5 / 10
#     有干净上文  9 / 10     ← ★ 差 4 分全在"能不能看到聊天记录"✓
#     有噪声上文  8 / 10
#   —— ★ 所以这个功能要和【读上下文】配合用才发挥得出来 ✓
#
# ★ 关键词优先 ✗ 小模型兜底：
#     规则里那 15 类社交语气（打招呼 / 分别 / 感谢 / 夸奖 …）
#     关键词判得又快又准 ✗ 一律不问小模型 ✓
#     只有关键词【什么都没找到】（plain）时才问 ✓
#   —— ★ 所以最坏情况 = 回到现在的行为 ✗ 不会更差 ✓✓✓
#
# ★ 电脑版没有这个 ✗ 因为电脑版可以直接用大模型 ✓

# ---------------- 条件替换（看情况才换）----------------
# 上面那些写法是【无条件】的 ✧ 只要出现就换 ✓
# 下面这种写法可以【满足条件才换】✧ 能看懂上下文 ✓
#
# 格式：    如果 <条件> 就将 <原文> 替换成 <换成什么>
# 多个条件用【，】隔开 ✧ 全部满足才生效 ✓
#
# 支持这些条件：
#     含"某某"        整句里有这几个字
#     不含"某某"      整句里没有
#     前有"某某"      紧挨在前面
#     后有"某某"      紧挨在后面
#     在句首          这个词在开头
#     在句尾          在结尾
#     整句是"某某"    整句就等于它
#     长度>=5         字数条件（>= <= > < = 都行 ✓）
# ★ 手机版注意：安卓引擎已经认这两个条件了 ✗
#   但"从聊天窗口读上下文"这部分还没接 ✗ 所以目前写了也不生效 ✓
#   —— ★ 不会报错 ✗ 也不会乱换 ✗ 只是不动 ✓
#

#     上文含"某某"      聊天上下文（对方最近说的）里有这几个字
#     上文不含"某某"    上下文里没有
#
# ★ 这两个要【看聊天记录】✗ 和上面那七种不一样 ✓
#
#   例子：
#       如果 上文含"考砸" 就将 没事的 替换成 没事的啦
#       如果 上文含"谢谢" 就将 不客气 替换成 不用谢
#       如果 上文不含"晚安" 就将 好 替换成 好呀
#
# ★ 读不到聊天记录时 ✗ 这两条【都不会生效】✗ 不会乱换 ✓
#   （读不到的情况：没开 QQ/微信 ✗ 用的不是这两个 ✗ 界面变了 ✓）
#   —— ★ 宁可不动 ✗ 也不猜错 ✓

# ★ 电脑版怎么读：
#     开着 QQ / 微信 ✗ 转换时自动看一眼当前聊天窗口的最近几条 ✓
