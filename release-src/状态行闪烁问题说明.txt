【一】这是什么程序
--------------------------------------------------------------------------------
  · C# / WinForms，.NET Framework 4.8，用 csc.exe 编译（C# 5 语法，不能用新特性）
  · 一个聊天输入框增强工具：打完字按热键，整行文字会被加上后缀 + 颜文字
  · 界面是自绘风格：卡片继承 Panel 并重写 OnPaint 画圆角背景
  · 近期加了【中英双语】：界面上几百处中文硬编码，靠一个 Lang 类
    在运行时遍历控件树、查字典、把 .Text 换成英文


【二】问题现象
--------------------------------------------------------------------------------
  点左下角的「中文 / English」按钮切换语言时，
  状态行那一小块文字会【先被裁短一帧到两帧，再恢复】。

  逐帧读视频（60fps）实测到的序列：

      f40 (0.667s)   完整中文
                     "生效: QQ, Code, Weixin · 立即转换 Ctrl+Shift+M ·
                      自动 700ms · 语气 开"

      f41 (0.683s)   ★ "生效: QQ, Code"          ← 后半段不见了
      f42 (0.700s)   ★ "生效: QQ, Code"

      f43 (0.717s)   完整英文
                     "Active: QQ, Code, Weixin · Transform Ctrl+Shift+M ·
                      Auto 700ms · Tone off"

  · 大约两帧 ≈ 30~50 毫秒，肉眼就是"闪一下"
  · 只有状态行这一行有问题，同一张卡片里的四个数字、右侧栏的卡片都正常
  · 字一个都没少，最后显示完全正确
  · 中文→英文 和 英文→中文 都有


【三】时间线：从哪一步开始出现这个问题的
--------------------------------------------------------------------------------
  用户原话："我说下面那段文字慢半拍以后，你改完就变成这样会闪一下"

  步骤 A（问题一：慢半拍）
      改之前：状态行比界面上其他文字晚变，最多晚 700ms
      原因：  这行是 statusDetail，标了 Lang.NoTranslate
              （因为它由代码按语言拼出来，不能让自动翻译碰）
              于是只能靠 RefreshStatus 自己刷
              而 RefreshStatus 是 700ms 定时器驱动的

  步骤 B（修法 A：补刷新）★ 就是这一步引入了闪烁 ★
      在三个地方显式补了 RefreshStatus()：
          · 语言按钮的 Click
          · ApplyLookAt（点外观风格）
          · ApplyToneAt（点语气）

  步骤 C（问题二：闪烁）
      改完之后不慢半拍了，但状态行会闪一下

  结论：闪烁是【步骤 B 多刷了一次】造成的。


【四】为什么多刷一次就会闪
--------------------------------------------------------------------------------
  语言按钮 Click 里的顺序（改之前）：

      app.Cfg.Language = "en";        // 1. 先改内存里的语言
      app.PatchRules(kk);             // 2. 写文件 + 重载规则
                                      //    ★ 它内部会调 RefreshStatus
                                      //    ★ 但那时 Lang.English 还是旧值
                                      //    → 刷出来的是【旧语言】的文字
      Lang.English = true;            // 3. 到这里才更新翻译开关
      Lang.Apply(this);               // 4. 遍历控件树，把文字换成英文
      RefreshStats();                 // 5. 刷统计
      RefreshStatus();                // 6. 我新加的 —— 这次是【新语言】
      langBtn.Text = "English";

  → 第 2 步画出一次【旧语言】的状态行
  → 第 6 步画出一次【新语言】的状态行
  → 中间那两帧就是"先旧后新"的过渡

  本来我给 statusHead / statusDetail / statusWarn 都加了
  "值没变就不写"的判断，但这里两次的值【确实不同】，所以两次都写了。


【五】到目前为止试过的所有改法（都没彻底解决）
--------------------------------------------------------------------------------
  说明：这些改动【目前都还在代码里】，不是回滚掉重来。

  1. 冻结重绘 + 解冻后统一标脏
     · Lang.Freeze(root)：SendMessage(hwnd, WM_SETREDRAW, 0, 0)
                          + root.SuspendLayout()
     · Lang.Thaw(root)：  恢复 WM_SETREDRAW + ResumeLayout(false)
                          + 标脏 + 异步 Update
     · 语言按钮的 Click 改成：
          Lang.Freeze(this);
          try { 原来的全部逻辑 }
          finally { Lang.Thaw(this); }
     目的：让整个切换过程只画最后那一帧

  2. 只标脏"真的改过 .Text 的控件"，不用 Invalidate(true)
     · Walk 里把改过的控件记进 dirtyControls 列表
     · 解冻后只对这些控件 Invalidate
     原因：之前用 Invalidate(true) 整树标脏，会【先擦白再一个个画】，
           实测出现三帧"擦掉了还没画完"的空白

  3. 标脏和 Update 投递到消息队列（BeginInvoke）
     原因：怀疑刚解冻时布局还没跑，控件宽度还是 0，
           Invalidate 标的区域偏小，只重绘了左边一小块

  4. 状态行的分隔符换成不换行空格 U+00A0
     原因：一开始以为是文字被挤成多行
     结果：没用。因为根本不是换行，是【被裁掉】

  5. 去掉 langOnce 定时器里的第二次 Apply
     原因：它是 40ms 后兜底再翻一次的，会造成第二次整树重绘

  6. 去掉 FillRailRules / FillRailKaomoji 里的 SuspendLayout / ResumeLayout
     原因：怀疑它们挂在卡片自己身上，绕过外层的 SuspendLayout
           （WinForms 的 SuspendLayout 是每个控件独立计数的）
     结果：仍然会闪


【六】界面结构（可能有关）
--------------------------------------------------------------------------------

    │
    ├─ TableLayoutPanel 「状态区」
    │     ├─ 四个数字卡（StatCard，自绘 Panel + 三个 Transparent Label）

          │
          ├─ 卡片「颜文字库」

【七】已经确认排除的可能
--------------------------------------------------------------------------------
  ✗ 不是数据错误 —— 每次刷新读到的值都是对的
  ✗ 不是没画完   —— 同一区域的其他控件（四个数字卡）完全正常
  ✗ 不是换行     —— 换成不换行空格没有任何改善
  ✗ 不是整树重绘 —— 已经改成只标脏改过的控件
