④ 输入 / 输出框改成「你说 / 喵化结果」双卡片

现状（MainActivity.buildTestCard，326 行起）：
   一张卡里塞了四样东西 —— 说明文字、「喵化之后」标签、testIn（EditText）、
   testOut（TextView，绿色 OK 字）。

改法：
   · 拆成两张卡，各自有标题：
        上面：「你说」   → testIn
        下面：「喵化结果」→ testOut
   · 去掉那个夹在中间的「喵化之后」小标签（新标题取代它）
   · testOut 的字色从 OK（绿）改成 TEXT 或 ACCENT —— 绿色在这个配色里不搭
   · testOut 加上 SOFT 底色，和输入框区分开
   · 顶部那句说明「在下面随便打几个字…」保留，但缩到一行

风险：低。只是重排已有控件，没有新的数据流。

⑤ 底部导航加图标 + 「关于」改成「我的」

现状（buildTabBar，228 行起）：
   5 个 tab，只有文字，没有图标。
   TABS 数组在 182 行：
       { "试一下", "风格", "规则", "设置", "关于" }
   ★ 注意实际用的是【短名】—— 不是"喵化风格""喵化规则"。
     手机屏幕窄，当初就缩过了。改的时候别把它改长。
   ★ 而且「关于」要改成「我的」—— 两个字的长度一样，不影响排版。

尺寸测算（⑤ 能不能放下的依据）：
   现在：文字 13sp(≈18dp) + 上下内边距 10+10 = 38dp，再加导航条 6+6 = 50dp 高
   加图标后：图标 18dp + 间隙 2dp + 文字 18dp + 内边距 6+6 = 50dp，条 6+6 = 62dp
             → 高 12dp，可以接受
   宽度：360dp 屏 - 条内边距 12dp = 348dp，÷5 = 69.6dp 一格，
         减去格间 4dp = 65.6dp 可用
         最长的「试一下」3 字 × 13sp ≈ 39dp → 装得下，还有余量
   结论：加图标【放得下】，不用改文字大小，也不用减 tab 数量。

改法：
   · 每个 tab 变成「图标 + 文字」竖排
   · 图标用 Android 自带的 android.R.drawable（不引第三方资源，安装包不长大）：
        试一下    → ic_menu_edit 或 ic_media_play
        喵化风格  → ic_menu_manage 或 star
        喵化规则  → ic_menu_agenda
        设置      → ic_menu_preferences
        我的      → ic_menu_myplaces 或 ic_menu_info_details
   · 「关于」改成「我的」—— ★ 注意：这是目标里要求的，【电脑版仍叫「关于」】，
     所以改完之后两边叫法【不一样】。之前我在这个文件里写"和电脑版一致"是错的。
   · 选中态：图标 + 文字一起用 ACCENT，背景仍用现在的 SEL_BG

风险：低。但要确认 5 个 tab 在窄屏上不会挤 —— 图标 18dp + 文字 11sp 竖排，
每个 tab 约占 20% 宽度。

⑥ 首页加「Lv. 喵化等级 / 今日喵化次数」

★ 这一项【不是改界面】，工作量比 ④⑤ 大得多 ★

安卓端现在【完全没有统计】：
   持久化里只有 look / tone（当前风格名）、rules 文本、rev 计数器。
   没有喵化次数、没有等级、没有今日次数。

所以要先补引擎侧的统计，再谈界面。分三步：

  ⑴ 统计与持久化
     新建 Stats.java（对照电脑版的 Stats 类）：
         total      累计喵化次数
         today      今日次数
         day        日期（换天就归零 today）
     存 SharedPreferences，键名和电脑版对齐：
         stats_total / stats_today / stats_day
     或者单独一个 stats.txt —— 电脑版是单独文件，安卓用 SharedPreferences
     更自然，两者行为一致即可（换天归零的规则必须一样）。

  ⑵ 计数点
     在 MiaohuaService 里【真正写入成功之后】加一次。位置很关键：
       · 不能放在"决定要转化"的地方 —— 写失败会多算
       · 参考电脑版：它是写入成功后 +1
     这里要小心：安卓是 ACTION_SET_TEXT 异步写，没有可靠的写入完成回调，
     所以只能"提交之后"就计数。要在注释里写清这个差别。

  ⑶ 等级规则
     电脑版：public const int PerLevel = 40;   Level = 1 + Total / PerLevel;
     安卓照抄，不要另发明一套 —— 两边等级必须一样。

  ⑷ 界面
     首页头部下面加一行，或做成一张小卡片：
         Lv.2        今日 4 次        累计 71 次
     数据从 Stats 读，onResume 时刷新。

风险：中。要动引擎（MiaohuaService + 新增 Stats），而且按硬规则
      「改引擎必须两个引擎一起改」—— 但电脑版已经有了，所以这里是
      【向电脑版对齐】，不是各改一半。

打包顺序的坑（我栽过两次）
------------------------------------------------
pack-all.ps1 会清理配送目录 D:\喵化助手。
所以复制 APK 必须在【打包完成之后】，否则刚复制过去的 APK 会被清掉。

正确顺序：
  1. build-apk.ps1
  2. pack-all.ps1
  3. Copy-Item android\Miaohua.apk  D:\喵化助手\喵化助手_安卓版_v3.2_美化试验.apk
  4. 只复制 3.2 那两个 zip（别用通配符把根目录里的旧包又带进去）
